# Workspace Audit — Performance, Memory, Correctness

**Date:** 2026-08-25
**Branch:** `tui-perf-and-correctness`
**Scope:** all 7 crates, ~134,000 lines of Rust, every `src/` file read by 7 parallel review agents.
**Warning:** this repo is edited by another agent during sessions. Line numbers can drift. File names stay correct.

---

## 1. Bugs that break things (fix these first)

### B1 — Tool approval never shows. HIGH
Extensions replace the approval hook. The hook slot holds only one hook.
- `crates/pirust-coding-agent/src/runtime_host.rs:467-485` (`install_extension_hooks`) calls `set_before_tool_call` and replaces the approval hook set at `runtime_host.rs:189`.
- `set_before_tool_call` is single-slot replace (`pirust-agent-core/src/agent.rs:410`).
- `main.rs:567` binds extensions before `InteractiveMode::new` registers the decider (`interactive_mode.rs:585`).
- Result: in interactive mode, bash/edit/write run with **no approval prompt**. The approval UI (`interactive_mode.rs:1119-1194`) is dead code in production.
- **Fix:** compose extension hook + approval decider into one closure, or make `install_extension_hooks` chain the previously installed hook.

### B2 — Ctrl+C / Esc locks the agent forever. HIGH
- TUI cancels a turn with `JoinHandle::abort()` (`interactive_mode.rs:688-696`).
- `run_with_lifecycle` clears `active_run`/`idle` only in straight-line code after the await, no drop guard (`pirust-agent-core/src/agent.rs:659-685`).
- Aborting drops the future mid-await → `finish_run()` never runs → every next prompt fails `BusyPrompt`, `wait_for_idle` hangs.
- `Agent::abort()` (`agent.rs:437-441`, the real cancellation-token path) is never called from the TUI.
- **Fix:** on cancel, call the agent's abort and let the task finish. Also add an RAII drop guard in `run_with_lifecycle` as defense in depth. Same wedge exists in `AgentHarness::prompt` (`harness/mod.rs:587-633`).

### B3 — "Thinking level" is never sent to the model. HIGH
- `pirust-agent-core/src/agent.rs:583`: `let _reasoning = ...` — computed, then dropped. `AgentLoopConfig` has no reasoning field; `run_loop` hard-inits `reasoning = None` (`agent_loop.rs:230`).
- Harness remaps it via `prepare_next_turn`, but that runs only **after** turn 1 — the first provider call of every prompt runs with reasoning off.
- Also the Anthropic `build_request` never serializes a `thinking` block at all; `thinking_enabled`, `budget`, `effort`, `sampling_params`, `metadata.user_id` are all silently dropped (`pirust-ai/src/api/anthropic_messages.rs:832-911`), while line ~854 still suppresses `temperature` "because thinking is enabled".
- **Fix:** add a reasoning field to `AgentLoopConfig`, seed it, and emit the `thinking` block in the Anthropic body.

### B4 — 3 of 4 API adapters do not stream. HIGH
- `openai_completions.rs:2158-2177`, `openai_responses.rs:337-364`, `azure_openai_responses.rs:364-391`: all SSE events are collected into a `Vec<Value>` until the stream ends, then replayed. The consumer sees nothing until the answer is complete, and the whole response is held in memory as parsed JSON.
- Only the Anthropic adapter streams.
- **Fix:** feed each parsed chunk into the state machine inside the `while let Some(item) = events.next().await` loop (the state machine is already synchronous per chunk).

### B5 — Big pastes get broken characters. HIGH
- `pirust-tui/src/terminal.rs:476-491` reads stdin in 4096-byte chunks; each chunk goes through `String::from_utf8_lossy` (`stdin_buffer.rs:269-276`).
- A multi-byte character cut at a chunk edge becomes U+FFFD in both chunks. Guaranteed for any >4 KB paste with non-ASCII text.
- **Fix:** hold back the trailing incomplete UTF-8 sequence between reads and prepend it to the next chunk.

### B6 — The app can hang at exit. HIGH
- `ProcessTerminal::stop()` joins the reader thread (`terminal.rs:353-355`), but that thread is blocked in `stdin.read()` with no wakeup. Exit stalls until a key is pressed.
- **Fix:** detach the reader thread, or use a cancellable read.

### B7 — No timeout, cancel, or retry on the Anthropic path
- `anthropic_messages.rs:244-352` never reads `opts.base.signal`, `max_retries`, or `timeout_ms`. `http/mod.rs:117-123` builds the client with no timeout. A stalled connection hangs forever; the request cannot be aborted.
- **Fix:** wrap the POST in `retry_provider_request`, `select!` against `signal.cancelled()`, apply `timeout_ms`.

### B8 — WASM hot-reload does not reload changed extensions
- `pirust-coding-agent/src/runtime_host.rs:610-647`: reload fully compiles + instantiates + activates every `.wasm`, then drops all whose path is already loaded. A **modified** file at an existing path is never swapped in; unchanged ones are recompiled for nothing.
- **Fix:** filter paths against loaded extensions before compiling; key on path+mtime/hash and actually replace changed ones.

### B9 — Extension header hook does nothing
- `pirust-extension-api/src/runner.rs:322-351`: `before_provider_headers` handlers get an immutable event and their return value is discarded; the unchanged headers are copied back. Extensions can never modify provider headers.
- **Fix:** adopt the `emit_before_provider_request` pattern (take the returned value as the new headers).

### B10 — Abort mid-tool-batch breaks session resume
- `agent_loop.rs:652-655` (sequential) and `:687-697` (parallel): abort breaks out, leaving assistant `tool_use` blocks without matching `tool_result`s. Anthropic rejects the resumed session.
- **Fix:** synthesize "Operation aborted" error results for every remaining tool call.

### B11 — File writes can corrupt data
- `settings.rs:1256` writes `settings.json` truncate-in-place; `session.rs:1609-1618` does the same to whole session files during v1→v3 migration. A crash mid-write leaves a truncated/empty file — migration can destroy the whole history.
- `settings.rs:1183-1203`: the settings lock has no staleness check (auth.rs:507-532 has one). A killed process blocks all settings writes until the lock dir is deleted by hand.
- **Fix:** temp file + rename for both; copy auth's stale-lock break into settings.

### B12 — Orchestrator event pipeline bugs
- Out-of-order delivery: one `tokio::spawn` per runtime event (`sessions.rs:438-455`) has no FIFO guarantee — deltas can reach clients out of order. **Fix:** one ordered per-session mpsc consumer.
- One stalled client freezes everyone: `write_all` with no deadline under the writer mutex (`transports/unix/listener.rs:212-236`), serial fan-out, and the global broadcast lock held across sends (`snapshots.rs:74-77`). `max_pending_bytes` is effectively dead code. **Fix:** bounded per-connection outbound queue with its own writer task; disconnect on overflow.
- Sessions never evicted (`agent_service/service.rs:208-212`); an Arc cycle (listener closure captures `Arc<AgentHarness>`, `runtime.rs:121-142`) would leak them anyway. **Fix:** capture `Weak`, add remove-on-dispose / idle TTL.
- `dispose()` neither aborts an in-flight turn nor detaches listeners (`runtime.rs:235-238`).
- `maybe_dispose` gate is TOCTOU-racy vs concurrent attach (`sessions.rs:658-682`).
- Accept loop hot-spins at 100% CPU on persistent accept errors (`listener.rs:457-464`).
- Progress-event ids change per event for the same message (`conversions.rs:365-381`) — clients cannot reconcile items.

### B13 — Silent error swallowing
- Session persistence errors ignored: `let _ = self.session.append_message(...)` (`harness/mod.rs:311`); the transcript write is dropped and the run continues.
- Extension replies that fail to parse become defaults (`runner.rs:202-203` etc.): a malformed "block this tool" reply becomes "allow".
- Guest host-call payload parse failure becomes `Null` and still executes (`wasm/loader.rs:360`).
- **Fix:** surface all three as errors.

### B14 — Smaller correctness items
- SSE: a CRLF split across TCP chunks splits one event into two (`pirust-ai/src/sse/mod.rs:152-165`). Hold a trailing lone `\r`.
- `tool_call_blocks_by_index.clear()` in `ensure_text_block`/`ensure_thinking_block` (`openai_completions.rs:2684,2712`) duplicates tool-call blocks on interleaved streams. Delete both calls.
- No turn cap: a model repeatedly hitting `Length` with tool calls loops forever (`agent_loop.rs:942-945`).
- Tool `on_update` progress is buffered and emitted only **after** the tool finishes (`agent_loop.rs:826-874`) — long tools show no live progress.
- HashMap vs JS insertion-ordered Map divergences: branched-session label order (`session.rs:2432-2443`, `labels_by_id`) and v4 `find_open_operations` (`v4/state.rs:63,385`). Use `Vec`/indexmap.
- v4 storage appends the file line **before** `apply_mutation` (`v4/storage.rs:264`); a mutation failure desyncs file vs memory and the file becomes unloadable.
- WASM: a panicking bound runtime closure poisons the store and bricks the extension (`wasm/loader.rs:374-426`); abort/shutdown closures run under two mutexes → re-entrancy deadlock risk (`loader.rs:407-414`). Wrap dispatch in `catch_unwind`; make bound closures signal-only.
- `find_bash_on_path` leaks the probe child on timeout (`pirust-tools/src/bash.rs:403-436` — no `kill_on_drop`); `SpawnProbe::command_exists` waits with no timeout (`binaries.rs:493-511`).
- Unix socket: chmod happens after the socket is publicly linked (`listener.rs:509-526`) — pre-chmod connect window under permissive umask.
- Lone ESC keypress is not delivered until the next byte (`StdinBuffer::flush()` never called; `terminal.rs:42-55`) — Escape is the SelectCancel key, so this is user-visible.
- Steering messages drained then dropped on `BusyPrompt` (`agent.rs:486-494`).
- TUI "context tokens" metric sums every turn's input (quadratic overcount, `runtime_host.rs:655-664`); read the **last** assistant message's usage instead.

## 2. Biggest speed wins

### S1 — Stop cloning the full message on every streamed token (O(n²))
The single biggest cost. Each delta copies the whole accumulated message. Four layers do it:
- `pirust-ai`: `sink.push(partial: output.clone())` per delta (`anthropic_messages.rs:542-579` and the OpenAI equivalents), into an **unbounded** channel (`stream/mod.rs:58`).
- `pirust-agent-core`: each delta clones the partial twice, plus once per listener (`agent_loop.rs:489-504`, `agent.rs:755-791`).
- `pirust-tui`: see S3.
- `pirust-orchestrator`: worst case — every delta triggers a **full-transcript snapshot**, converted and CBOR-encoded **per connected client** (`agent_service/runtime.rs:128-176`, `sessions.rs:547-563`).
**Fix:** wrap snapshots in `Arc<AssistantMessage>`; orchestrator sends snapshots only on `MessageEnd`/phase change, deltas as `Progress` only; encode each broadcast frame once, not per connection.

### S2 — Compile once, use many times
- JSON schema validator recompiled on **every tool call** (`agent_loop.rs:1066-1070`); `tool.parameters()` also rebuilds the schema Value each turn. Cache compiled `Validator` per tool.
- ~80 `fancy_regex` patterns rebuilt on **every bash call** in plan mode (`pirust-extension-api/src/plan_mode.rs:94-104`; `trailing_stars` compiled inside a loop at `:168`). Use `LazyLock`.
- LaTeX symbol tables (~200-entry maps) rebuilt per parsed command, `blackboard()` per character (`pirust-tui/src/latex.rs:564-681`). Use `LazyLock`.
- Fresh `reqwest::Client` (new pool + TLS) per request (`anthropic_messages.rs:260` + 3 more). Share one `LazyLock<Client>`.
- `rg --version` / `fd --version` probe process spawned before **every** grep/find call (`binaries.rs:527-547`) — 5-30 ms per call on Windows. Cache with `OnceCell`/TTL.
- WASM: per-call `get_typed_func`/`get_memory` lookups and a fresh `Engine` per load (`wasm/loader.rs:59-64,229-255`). Resolve funcs once at load; share the engine.

### S3 — TUI: stop copying the whole document per frame
Terminal **writes** are correctly diff-bounded. CPU is not:
- Every frame walks all children and clones every cached line — full transcript deep-copy for a 1-char change (`tui.rs:1771`, `components/text.rs:79-82`, `box_component.rs:151`, `markdown.rs:230`). **Fix:** `Rc<[String]>`/`Cow` returns or per-child dirty flags.
- Editor computes the full text layout **twice** per frame (`editor.rs:1806` and `:1888` — the second call exists only for `.len()`). Capture the len first. Arrow keys rebuild the visual line map 2-4× per keystroke (`editor.rs:505,1300`).
- `visible_width` allocates a String for every non-ASCII input even with no tabs/ESC (`utils.rs:283`); it runs in nested loops. Iterate graphemes on `&str`, materialize only when needed.
- Cursor positioning is 2-3 separate write+flush syscalls per frame outside the synchronized-update buffer (`tui.rs:2003-2123`). Coalesce into one write.

### S4 — Edit tool: normalize once
`apply_edits_to_normalized_content` re-runs full-file NFKC normalization per edit, and `count_occurrences` re-normalizes file **and** needle unconditionally (`edit_diff.rs:631-684`). Hoist one normalized copy; output is bit-identical.

### S5 — Add a fast global allocator
No custom allocator anywhere in the workspace. The default Windows heap is slow for allocation-heavy code like this. Add `mimalloc` in `pirust-coding-agent/src/main.rs`:
```rust
#[global_allocator]
static GLOBAL: mimalloc::MiMalloc = mimalloc::MiMalloc;
```
One small change, whole-program gain.

### S6 — Misc
- Tool-call args re-parsed from index 0 on every delta; JSON-repair fallback allocates `Vec<char>` of the whole buffer (`anthropic_messages.rs:569`, `json_repair/mod.rs:46,197`). Parse only at block stop, or throttle.
- SSE line drain copies the remaining buffer per line (`sse/mod.rs:154-165,269-276`). Byte cursor + one `drain` per chunk.
- `build_params` deep-clones the full message array twice plus the whole params map to read one field (`openai_completions.rs:1429,1519,1531`).
- Blocking file I/O on the async runtime once per message (`jsonl_storage.rs:252-450`, `v4/storage.rs:420`). `spawn_blocking` or a writer thread.
- `sdk.rs:252-263` does a blocking auth.json read + full env snapshot per turn.
- RPC stdin lines JSON-parsed 3× each (`rpc/run.rs:68` + parse_input + parse_command_id).
- O(n²) session-append assistant scan (`session.rs:1930`); session lookup by id parses **every** session file in full (`session.rs:1362-1461`).
- `live_sessions` mutex held across full snapshot conversion (`sessions.rs:260-270`).
- UTF-8 stream decoder memcpys every chunk even when `pending` is empty (`output_accumulator.rs:186-220`).

## 3. Memory footprint

- Unbounded event channels hold full per-delta message snapshots (`pirust-ai/src/stream/mod.rs:58`) — O(n²) memory for one long response with a slow consumer. Bound the channel; `Arc` the payload.
- TUI holds the transcript ~3× (`previous_lines` + every `cached_lines` + component text, `tui.rs:378`), unbounded unless the app prunes. Editor undo stack clones the **entire** editor state per snapshot with no cap (`editor.rs:1486`, `undo_stack.rs`). Cap it (~100).
- Model catalog (1306 String-heavy models) held in ~4 copies (`models.rs:3298-3310,3478-3485`), rebuilt on key/config reload. Use `Arc<Model>` + index-based `available`. (catalog.rs itself is fine: generated constructors, zero runtime parsing, called once.)
- Orchestrator sessions never evicted + Arc cycle (see B12).
- `read` tool materializes the whole file ~2× to return a 50 KB truncated result (`read.rs:531-589`), repeated per `offset=` continuation. Stream and stop at the caps.
- Diff arena never frees pruned Myers paths — O(D²) retained, hundreds of MB on two large dissimilar texts (`edit_diff.rs:1112,987-1055`).
- `ServerSentEvent.raw` duplicates every SSE line for one error message (`sse/mod.rs:116`).
- grep context mode holds up to `limit` whole files as `Vec<String>` per call (`grep.rs:830-850`).
- `query_terminal_color_scheme` leaks a listener per call (`tui.rs:1164-1178`).
- Agent subscriptions are add-only (`agent.rs:340-342`).

## 4. What is good (verified)

- Build profile is well tuned: ThinLTO + 16 codegen units, strip, separate `fast` iteration profile. Catalog is compile-time generated — zero startup parsing.
- `pirust-tools` is the strongest crate: no zombies, no pipe deadlocks (stdout/stderr drained concurrently), multi-byte-safe truncation, sound edit-match/CRLF handling, RAII mutation-queue release.
- WASM sandbox limits are truly enforced (fuel + StoreLimits + trap_on_grow_failure); guest pointers/lengths bounds-checked everywhere.
- Session store is append-only (no full rewrite per message); torn-tail repair atomic; v4 codec strictly validates untrusted lines; auth.json locked, 0600, stale-lock breaking.
- RPC framing (LF-only, UTF-8 chunk-safe) correct; orchestrator CBOR frame decoder handles partial frames with an allocation guard.
- TUI terminal writes are genuinely diff-bounded with synchronized-update batching and an O(n) diff.

## 5. Root-cause pattern

Most bugs cluster at TS→Rust port seams:
- JS `Map` keeps insertion order; `HashMap` does not (B14 label/open-op ordering).
- JS is single-threaded; tokio is not (B12 TOCTOU, out-of-order spawns).
- JS GC frees pruned graphs; Rust arenas do not (diff arena).
- JS promise chains are ordered; spawned tasks are not (B12, handshake queue).
When porting more TS, check these four seams first.

## 6. Recommended fix order

1. B1, B2 — approval bypass + Ctrl+C wedge (interactive mode is unsafe/unusable without them).
2. B5, B6 — TUI stdin corruption + exit hang.
3. B3, B4, B7 — thinking level, adapter streaming, timeout/cancel.
4. S1 + S2 + S5 — Arc snapshots, cached validators/regexes/client, mimalloc.
5. B11 — atomic writes + stale settings lock.
6. Rest in listed order.
