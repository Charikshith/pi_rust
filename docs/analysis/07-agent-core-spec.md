## Executive summary (~25 lines)

1. `packages/agent` has three layers: pure loop functions (`agent-loop.ts`), a stateful `Agent`
   (`agent.ts`), and a batteries-included `AgentHarness` (`harness/agent-harness.ts`). The harness
   calls `runAgentLoop` directly, NOT the `Agent` class.
2. **`EventStream<T,R>` is pi-ai's primitive** (imported from `@earendil-works/pi-ai/compat`,
   agent-loop.ts:9). It is ALREADY ported at `crates/pirust-ai/src/stream/mod.rs`. **Reuse it** —
   do not re-implement in agent-core.
3. **CRITICAL ORACLE CORRECTION:** the two vendored JSONL files
   (`coding-agent/test/fixtures/{before-compaction,large-session}.jsonl`) are **v1 legacy-format**
   sessions owned by `packages/coding-agent`, NOT the agent-core **v3** tree format. They have no
   `version`, no per-entry `id`/`parentId`, and compaction uses `firstKeptEntryIndex` (a number),
   not `firstKeptEntryId` (a string). agent-core's `JsonlSessionStorage` REJECTS them
   (jsonl-storage.ts:70,114). They require `migrateSessionEntries()` in coding-agent
   (coding-agent/test/compaction.test.ts:38). Use them only to (a) confirm v1 entry-type coverage
   and (b) test a v1→v3 migration path — NOT as a v3 byte oracle.
4. The real v3 byte oracle is generated by driving `JsonlSessionStorage`/`Session` in Node with
   fixed ids/timestamps (recipe in §11.A). JS `JSON.stringify` object-literal key order + `undefined`
   omission is the byte-identity contract; Rust serde needs matching field order +
   `skip_serializing_if = "Option::is_none"`.
5. Session transcript is an append-only **tree**; a `leaf` entry repoints the current leaf
   (branch/fork/time-travel). Context building collapses everything before a compaction's
   `firstKeptEntryId` into just the summary (session.ts:57).
6. Compaction cut-point selection (`findCutPoint`, compaction.ts:333) is fully deterministic and
   unit-testable; the summary TEXT is LLM-generated (non-deterministic) — there is **no golden
   after-compaction fixture**; tests assert structure with a faux summarizer.
7. Token estimate uses JS `string.length` (UTF-16 units), `ceil(chars/4)`, image = 4800 chars
   (compaction.ts:205,224). Rust must count UTF-16 units for identity.
8. Behavioural oracle: pi-ai's `fauxProvider` + scripted `setResponses(...)` drives `runLoop`/
   `AgentHarness` fully offline (recipe §11.B). Ported to Rust already.
9. UUIDv7 (uuid.ts) is hand-rolled with module-level `lastTimestamp`/`sequence` monotonic counters
   and an exact 16-byte layout (§7). Randomness/clock are NOT injectable in Pi — the Rust port must
   add an injection seam for deterministic vectors; the algorithm itself is the oracle.
10. Async traits to port: `FileSystem`, `Shell`, `ExecutionEnv`, `SessionStorage`, `SessionRepo`,
    `AgentTool`. `AbortSignal` → `tokio_util::sync::CancellationToken`.
11. Proposed layout mirrors index.ts; decomposition into ~8 independent leaf modules + 1 integrator
    (agent_loop + harness) for parallel subagents (§13).

## 1. `types.ts` — persisted/serialized types

### 1.1 Message model (types.ts:305-314, messages.ts:19-61)

- `AgentMessage = Message | CustomAgentMessages[keyof CustomAgentMessages]` (types.ts:314).
- `Message` (from pi-ai) = `UserMessage | AssistantMessage | ToolResultMessage`.
- `CustomAgentMessages` (types.ts:305) is an empty declaration-merging seam; `messages.ts:54-61`
  merges in FOUR agent-core-only variants via `declare module "../types.ts"`:
  - `bashExecution` → `BashExecutionMessage` (messages.ts:19-29)
  - `custom` → `CustomMessage<T>` (messages.ts:31-38)
  - `branchSummary` → `BranchSummaryMessage` (messages.ts:40-45)
  - `compactionSummary` → `CompactionSummaryMessage` (messages.ts:47-52)

`BashExecutionMessage` is defined at **messages.ts:19-29**. It is an agent-core message variant NOT
present in pi-ai's `Message`. Exact shape + key order (as constructed / serialized):
```
role:"bashExecution", command:string, output:string, exitCode:number|undefined,
cancelled:boolean, truncated:boolean, fullOutputPath?:string, timestamp:number, excludeFromContext?:boolean
```
On-disk sample (before-compaction fixture, wrapped in a `message` entry): key order
`role, command, output, exitCode, cancelled, truncated, timestamp` (fullOutputPath/excludeFromContext
omitted when absent). `exitCode:0` is present (not omitted; it's `number`, only `undefined` is omitted).

`CustomMessage`: `role:"custom", customType, content:string|(Text|Image)[], display:boolean, details?, timestamp:number`.
`BranchSummaryMessage`: `role:"branchSummary", summary, fromId, timestamp:number`.
`CompactionSummaryMessage`: `role:"compactionSummary", summary, tokensBefore, timestamp:number`.

**Rust:** one closed `enum AgentMessage` (`#[serde(tag="role")]`) with pi-ai's three + these four.
The declaration-merge seam is compile-time only; no runtime plugin. Tag values MUST match wire
strings exactly: `user`/`assistant`/`toolResult`/`bashExecution`/`custom`/`branchSummary`/`compactionSummary`.

### 1.2 Timestamp duality (byte-identity target)

- **Inner** `message.timestamp` is a **number** (`Date.now()` ms) — e.g. `1765233665292`.
- **Outer** session-tree-entry `timestamp` is an **ISO string** (`new Date().toISOString()`) —
  e.g. `"2025-12-08T22:41:05.306Z"` (session.ts:208,217,etc.).
- The custom-message *constructors* convert entry ISO string → number:
  `new Date(timestamp).getTime()` (messages.ts:86,99,116). So when a `custom_message`/`compaction`/
  `branch_summary` ENTRY becomes an in-context MESSAGE, its `timestamp` flips string→number.

## 2. `agent-loop.ts` — the engine

### 2.1 Public wrappers

- `agentLoop(prompts, context, config, signal?, streamFn?)` (31-54): builds an `EventStream` whose
  completion predicate is `event.type==="agent_end"` and result extractor returns `event.messages`
  (145-150), then `void runAgentLoop(...).then(m => stream.end(m))` — fire-and-forget detached task.
- `agentLoopContinue` (64-93): throws if messages empty (71) or last role is `assistant` (74).
- `runAgentLoop(prompts, context, config, emit, signal?, streamFn?)` (95-118): seeds
  `newMessages=[...prompts]` and `currentContext.messages=[...ctx.messages,...prompts]`; emits
  `agent_start`, `turn_start`, then `message_start`+`message_end` for each prompt (111-114); calls
  `runLoop`; returns `newMessages`.
- `runAgentLoopContinue` (120-143): same guards; `newMessages=[]`, `currentContext={...context}`;
  emits `agent_start`+`turn_start` only.

### 2.2 `runLoop` two-level loop (155-275)

Pre-loop: `pendingMessages = (await config.getSteeringMessages?.()) || []` (167).
**Outer** `while(true)` (170): restarts on follow-up. **Inner** `while(hasMoreToolCalls || pendingMessages.length>0)` (174). Per turn:
1. If not `firstTurn` emit `turn_start`; else clear `firstTurn` (175-179).
2. Inject pending: for each, emit `message_start`+`message_end`, push to `currentContext.messages`
   AND `newMessages`; clear pending (182-190).
3. `streamAssistantResponse(...)` (193) → `AssistantMessage`; push to `newMessages` (194).
4. If `stopReason` is `error` or `aborted`: emit `turn_end{toolResults:[]}` + `agent_end`, return (196-200).
5. Filter `toolCall` blocks (203). If any:
   - If `stopReason==="length"` → `failToolCallsFromTruncatedMessage` (**fail ALL** tool calls;
     truncated args unsafe) (211-213, impl 383-408, `terminate:false`).
   - Else → `executeToolCalls` (214).
   - Push results to `currentContext.messages` + `newMessages`; `hasMoreToolCalls = !batch.terminate` (216-221).
6. Emit `turn_end{message,toolResults}` (224).
7. `config.prepareNextTurn?.(...)` (232): may replace `context`; rebuild `config.model`/`config.reasoning`.
   Thinking mapping (238-244): `undefined`→keep; `"off"`→`reasoning:undefined`; else → the level.
8. `config.shouldStopAfterTurn?.(...)` (247): if true emit `agent_end`, return (255-257).
9. `pendingMessages = (await getSteeringMessages()) || []` (259).

After inner exits: `getFollowUpMessages()` (263); if non-empty set as `pendingMessages`, `continue`
outer (266-267); else `break` → emit `agent_end` (274).

### 2.3 `streamAssistantResponse` (281-374)

`transformContext?` (290-292) → `convertToLlm` (295) → build `Context{systemPrompt,messages,tools}`
(298-302) → resolve key `(getApiKey?(provider)) || config.apiKey` (307-308) → `streamFn(model, ctx,
{...config, apiKey, signal})` (310). Iterate stream: on `start` push partial into `context.messages`
+ emit `message_start` (321-326); on delta events replace last + emit `message_update{assistantMessageEvent}`
(328-346); on `done`/`error` fetch `response.result()`, replace-or-push, emit `message_start` only if
not already added, then `message_end`, return (348-361). Emitted message objects are **shallow copies**
(`{...partialMessage}`) except the final `message_end` uses `finalMessage` directly.

### 2.4 Tool pipeline (413-792)

`executeToolCalls` (413-428): batch is **sequential** iff `config.toolExecution==="sequential"` OR any
called tool has `executionMode==="sequential"` (421-424); else **parallel**.

Three stages per call:
- `prepareToolCall` (602-666): find tool (missing → immediate error `Tool X not found`); `prepareArguments`
  shim (588-600, **identity check**: returns original toolCall if `prepared===toolCall.arguments`);
  `validateToolArguments(tool, prepared)` (620); `beforeToolCall` hook (621-645, may `block` → error
  result with `reason`); abort checks after hook and again before returning (631,646). Any throw →
  immediate error result (659-664).
- `executePreparedToolCall` (668-709): `tool.execute(id, args, signal, onUpdate)`. `onUpdate` pushes
  `tool_execution_update` events, buffered in `updateEvents[]`, gated by `acceptingUpdates` — late
  updates after settlement are dropped (674,682,696,707). Await all update emits. Throw → error result.
- `finalizeExecutedToolCall` (711-755): `afterToolCall` hook (722), field-by-field merge of
  `content`/`details`/`terminate`/`isError` (736-743); hook throw → error result (744-747).

**Sequential** (435-489): per call emit `tool_execution_start`, prepare, execute+finalize (or immediate),
emit `tool_execution_end`, build+emit tool-result message; break on abort after each (480). Terminate =
`shouldTerminateToolBatch` (584-586: non-empty AND **every** result `terminate===true`).

**Parallel** (491-556): iterate — emit `tool_execution_start` in order; immediate outcomes resolved
inline (emit end immediately); prepared calls pushed as **thunks** (524-536). Then `Promise.all` over
thunks preserving array order (542-544); `tool_execution_end` fires inside each thunk (completion order,
534) but tool-result **messages** are emitted afterwards in **assistant source order** (545-550).

`createToolResultMessage` (774-787): `role:"toolResult"`, `toolCallId`, `toolName`, `content ?? []`
(null→[]), `details`, conditional `addedToolNames` (only if non-empty), `isError`, `timestamp:Date.now()`.
`createErrorToolResult` (757-762): `{content:[{type:"text",text:message}], details:{}}`.

## 3. `agent.ts` — stateful `Agent`

`AgentOptions` (97-121, 20 fields). `MutableAgentState` (60-94): copy-on-assign `tools`/`messages`
getters/setters. `PendingMessageQueue` (123-157): `drain()` returns all (`"all"`) or the oldest one
(`"one-at-a-time"`). `ActiveRun` (159-163): `{promise, resolve, abortController}`.

Single-active-run guard: `prompt()`/`continue()` throw if `this.activeRun` set (338-342,349-351);
`runWithLifecycle` (469-492) also re-checks (470). Lifecycle: create `AbortController`, set
`isStreaming=true`, run executor; on error `handleRunFailure` synthesizes an `assistant` message with
`stopReason` aborted/error + `errorMessage` and drives `message_start→message_end→turn_end→agent_end`
through `processEvents` (494-510); `finishRun` clears state and resolves the promise (512-518).
`waitForIdle()` awaits `activeRun.promise` (319-321). `abort()` calls `abortController.abort()` (310-312).

`createLoopConfig` (432-467) bridges options to `AgentLoopConfig`; `getSteeringMessages` honors a
one-shot `skipInitialSteeringPoll` flag (used by `continue()` from an assistant tail, 359-363).
`prepareNextTurn` prefers `prepareNextTurnWithContext` over `prepareNextTurn` (446-454).
`processEvents` (527-574) reduces state per event then awaits every listener **in subscription order**
(571-573) passing the run `signal`; throws if invoked outside a run (568-569). `continue()` from an
assistant tail drains steering (skip-initial) then follow-up, else throws
`"Cannot continue from message role: assistant"` (358-372).

**Rust:** `Agent` struct; `activeRun` as `Option<ActiveRun>` guarded by the single-task model (or a
`Mutex`/atomic). Listeners `Vec<Arc<dyn Fn(&AgentEvent, &CancellationToken)->BoxFuture>>`, awaited
sequentially. Preserve the fire-and-forget assistant-failure synthesis exactly.

## 4. `harness/agent-harness.ts` — orchestration & sessions

### 4.1 Structure

`AgentHarness<TSkill,TPromptTemplate,TTool>` (157). Phase FSM `idle|turn|compaction|branch_summary|retry`
(165). Public methods reject with `AgentHarnessError("busy")` unless idle (609,624,641,689,736).
Does NOT use the `Agent` class — calls `runAgentLoop` directly (565).

`createTurnState` (314-346): `session.buildContext()` (315) → snapshot messages, resources,
`cloneStreamOptions`, `sessionId`, resolved system prompt (string or callback, 322-334), model,
thinking, tools, activeTools. `createContext` (348-357) slices messages+activeTools.

`createLoopConfig` (399-448) bridges hooks into `emitHook`: `transformContext`→`context` event,
`beforeToolCall`→`tool_call`, `afterToolCall`→`tool_result`, and `prepareNextTurn` (435-444) FLUSHES
pending writes, rebuilds turn state, returns new context/model/thinking. `getSteeringMessages`/
`getFollowUpMessages` drain via `drainQueuedMessages` (387-397, unshift-back on hook error).

`createStreamFn` (359-385): wraps `models.streamSimple`; fires `before_provider_request` (mutates
stream options via `applyStreamOptionsPatch`, 82-122), `before_provider_payload` (via `onPayload`,
370), `after_provider_response` (via `onResponse`, 371-377).

### 4.2 Append-only tree writes + save points

Pending writes (`PendingSessionWrite[]`, 168) queued while a run is active; flushed at turn boundaries
by `flushPendingSessionWrites` (462-486, dispatches per `type`). `handleAgentEvent` (488-515):
`message_end`→append message + emitAny; `turn_end`→emitAny, flush writes, emit `save_point`
{hadPendingMutations}; `agent_end`→flush, phase=idle, emitAny, emit `settled`. Mutators
`setModel`/`setThinkingLevel`/`setTools`/`setActiveTools`/`appendMessage` append immediately when idle,
else queue a pending write (833-928). `emitRunFailure` (517-529) synthesizes a failure assistant
message and drives the normal event sequence.

### 4.3 Events

Two dispatch mechanisms. `subscribe()` (1003) registers a wildcard `"*"` listener receiving EVERY event
(`emitAny`/`emitOwn`, 212-230). `on(type,handler)` (1015) registers hooks whose return values mutate
behaviour (`emitHook`, 232-249, **last non-undefined result wins**, 241). Hook errors normalized to
`AgentHarnessError("hook")` (137-139). Event/result maps: `AgentHarnessOwnEvent` (types.ts:636),
`AgentHarnessEventResultMap` (types.ts:706).

### 4.4 Leaf-repointing (branch/fork/navigate)

`Session.moveTo(entryId, summary?)` (session.ts:318-337) sets the leaf and optionally appends a
`branch_summary` entry. `navigateTree` (732-827): computes old/target paths + common ancestor
(`collectEntriesForBranchSummary`, branch-summarization.ts:67-96), optional branch summary generation,
special-cases navigating to a `user`/`custom_message` target (repoints to `parentId`, returns
`editorText`, 782-803), then `moveTo` + emits `session_tree`. Fork logic in repo-utils
`getEntriesToFork` (32-51): `"at"`→target.id; `"before"` (default)→target must be a `user` message,
uses `target.parentId`.

`getPathToRoot` (jsonl-storage.ts:296-309, memory-storage.ts:115-128): walk `parentId` chain,
`unshift` (root-first). `defaultContextEntryTransform` (session.ts:57-80): find LAST compaction; emit
`[compaction, ...entries from firstKeptEntryId onward before compaction, ...entries after compaction]`
— everything before `firstKeptEntryId` is dropped. `deriveSessionContextState` (37-55) derives
model/thinking/activeTools from the path (assistant messages also update `model`, 47-48).

### 4.5 Compaction algorithm (compaction.ts) — precise

**Token counting.** `estimateTokens(message)` (224-264): sums chars then `Math.ceil(chars/4)`. Chars
via `estimateTextAndImageContentChars` (207-221): string→`.length` (**UTF-16 code units**), text
block→`text.length`, image→`ESTIMATED_IMAGE_CHARS=4800` (205). assistant: text `.length` +
thinking `.length` + toolCall `name.length + JSON.stringify(arguments).length` (234-245). bashExecution:
`command.length+output.length` (252-255). branch/compaction summary: `summary.length` (256-260).
`estimateContextTokens` (169-197): if a valid assistant `usage` exists, `tokens = usageTokens +
trailingTokens` (chars after last usage); else sum of all `estimateTokens`. `calculateContextTokens`
(118-120): `usage.totalTokens || input+output+cacheRead+cacheWrite`. `shouldCompact` (200-203):
`enabled && contextTokens > contextWindow - reserveTokens`.

**Cut-point selection.** `findValidCutPoints` (265-303): indices where a message entry has role
user/assistant/bash/custom/branchSummary/compactionSummary (NOT toolResult), plus branch_summary/
custom_message entries. `findCutPoint(entries,start,end,keepRecentTokens)` (333-381): walk backwards
accumulating `estimateTokens` of MESSAGE entries; once `>= keepRecentTokens`, pick the first cut point
`>= i` (352-359). Then walk `cutIndex` left while the previous entry is neither compaction nor message
(362-371). `isSplitTurn = !isUserMessage && turnStartIndex !== -1` (379); `turnStartIndex` from
`findTurnStartIndex` (306-320, first user/bash/branchSummary/customMessage at/before the cut).

`prepareCompaction` (545-610): returns `ok(undefined)` if empty or last entry is compaction (549).
Finds previous compaction → `previousSummary` + `boundaryStart` at its `firstKeptEntryId` (563-568).
`tokensBefore = estimateContextTokens(buildSessionContext(pathEntries).messages).tokens` (571).
`historyEnd = isSplitTurn ? turnStartIndex : firstKeptEntryIndex` (580). Builds `messagesToSummarize`
(582-585) and `turnPrefixMessages` (587-592) via `getMessageFromEntryForCompaction` (skips compaction
entries, 81-86). `fileOps` extracted from summarized history + prev compaction details (35-58).

`compact` (630-704): if split turn generates a history summary + a `TURN_PREFIX` summary joined with
`---` (655-679); else one summary. `generateSummary` (460-522): maxTokens `min(0.8*reserveTokens,
model.maxTokens)`; uses `SUMMARIZATION_PROMPT` or `UPDATE_SUMMARIZATION_PROMPT` (+ optional
`Additional focus:`); `serializeConversation(convertToLlm(msgs))` wrapped in `<conversation>`;
`models.completeSimple(...)`; error/aborted → `CompactionError`. Appends `formatFileOperations(...)`.
Result: `{summary, firstKeptEntryId, tokensBefore, details:{readFiles,modifiedFiles}}`.
`DEFAULT_COMPACTION_SETTINGS = {enabled:true, reserveTokens:16384, keepRecentTokens:20000}` (111-115).

**Branch summarization** (branch-summarization.ts): `prepareBranchEntries` (123-162) token-budgeted
reverse walk; `generateBranchSummary` (199-261) `maxTokens:2048`, prepends `BRANCH_SUMMARY_PREAMBLE`.

## 5. `EventStream<T,R>` — reuse pi-ai's

`agent-loop.ts:9` imports `EventStream` from `@earendil-works/pi-ai/compat`; it is the SAME primitive
as pi-ai's `packages/ai/src/utils/event-stream.ts` (push-based async iterator + `finalResultPromise`,
completes on first `isComplete` event). This is **already ported** in Rust at

## 7. UUIDv7 — exact bit layout & monotonic counter (uuid.ts)

Module-level state (uuid.ts:1-2): `lastTimestamp = -Infinity`, `sequence = 0`.

Algorithm (`uuidv7`, 15-49):
1. Fill 16 random bytes (`crypto.getRandomValues` or `Math.random()*256` fallback, 4-13).
2. `timestamp = Date.now()` (ms).
3. If `timestamp > lastTimestamp`: `sequence = random[6]*2^24 + random[7]*2^16 + random[8]*2^8 + random[9]`
   (a 32-bit seed from random bytes 6..9); `lastTimestamp = timestamp` (20-22).
   Else: `sequence = (sequence + 1) >>> 0` (uint32 wrap); if it wrapped to 0, `lastTimestamp++` (24-28).
4. Pack 16 bytes (30-46):
```
bytes[0..5]  = 48-bit lastTimestamp, big-endian: (ts / 2^40)&0xff, (ts/2^32)&0xff, (ts/2^24)&0xff,
               (ts/2^16)&0xff, (ts/2^8)&0xff, ts&0xff       // JS float division, NOT bit-shift
bytes[6]     = 0x70 | ((sequence >>> 28) & 0x0f)            // version 7 nibble + seq high
bytes[7]     = (sequence >>> 20) & 0xff
bytes[8]     = 0x80 | ((sequence >>> 14) & 0x3f)            // variant bits + seq
bytes[9]     = (sequence >>> 6) & 0xff
bytes[10]    = ((sequence & 0x3f) << 2) | (random[10] & 0x03)
bytes[11..15]= random[11], random[12], random[13], random[14], random[15]
```
5. Format (51-54): lowercase hex, dashes at `8-4-4-4-12`.

**Byte-level identity contract:** for identical `(lastTimestamp, sequence, random[10..15])` the 16
bytes are fully determined. `sequence` is a JS uint32; use `u32` with wrapping-add. `lastTimestamp` is
a JS number holding ms — the `/ 2^N & 0xff` steps are float divisions then truncation; in Rust use
`(ts as u64 >> (8*(5-i))) as u8` which is equivalent for a 48-bit ms value. Only random bytes 6,7,8,9
seed `sequence` on a new timestamp; bytes 10..15 land verbatim; bytes 0..5 come from `lastTimestamp`.

**Injection seam:** Pi injects NOTHING — it reads `globalThis.crypto`/`Math.random` and `Date.now()`
directly (module globals). For deterministic test vectors the Rust port MUST add an injection seam
(e.g. a `trait Uuidv7Source { fn now_ms(&self)->u64; fn fill_random(&self, buf:&mut [u8;16]); }` with a
default `SystemSource` and a `FixedSource` for tests). Vectors: pick a fixed `(now_ms, 16 random bytes)`,
compute the expected string by hand from the layout above, assert equality; also assert monotonic
behaviour by calling twice with the same `now_ms` (second call increments `sequence`).

**Short entry ids:** `generateEntryId` (jsonl-storage.ts:36-44, memory-storage.ts:28-36) uses
`uuidv7().slice(-8)` (last 8 hex chars = low bytes 13,14,15 = pure random tail) with up to 100
collision retries, falling back to the full uuid. `createSessionId` (repo-utils.ts:12-14) = full uuidv7.

### 11.A SessionTreeEntry BYTE oracle

**Coverage of vendored fixtures.** `before-compaction.jsonl` top-level types (1003 lines):
`session`(1), `message`(990: inner roles assistant 484 / toolResult 448 / user 55 / **bashExecution** 3),
`thinking_level_change`(5), `model_change`(5), `compaction`(2). `large-session.jsonl` (1019 lines):
`session`(1), `message`(914), `thinking_level_change`(103), `model_change`(1). Together they cover
`message`(user/assistant/toolResult/bashExecution), `thinking_level_change`, `model_change`, `compaction`.
They do NOT cover `active_tools_change`, `branch_summary`, `custom`, `custom_message`, `label`,
`session_info`, `leaf`.

**⚠ These files are v1 legacy format, NOT v3.** The header is
`{type,id,timestamp,cwd,provider,modelId,thinkingLevel,branchedFrom}` — **no `version:3`**, has extra
`provider`/`modelId`/`thinkingLevel`/`branchedFrom`. Entries are `{type,timestamp,message}` — **no
`id`, no `parentId`**. Compaction uses `firstKeptEntryIndex` (a number), **not** `firstKeptEntryId`.
agent-core's `parseHeaderLine` throws `unsupported session version` (jsonl-storage.ts:70) and
`parseEntryLine` throws `is missing entry id` (114). coding-agent loads them only after
`migrateSessionEntries(entries)` (coding-agent/test/compaction.test.ts:38). **So they are a valid
oracle for a v1-parse + v1→v3 migration path, and for entry-type coverage — but NOT for the v3
serializer's byte identity.**

**Build the true v3 per-entry byte corpus** by driving the v3 storage with fixed inputs in Node
(`pi_space/pi/packages/agent`), one `JSON.stringify(entry)` per line:

### 11.B Behavioural oracle (offline, faux provider)

pi-ai's `fauxProvider` (`packages/ai/src/providers/faux.ts`) is the offline driver. `setResponses([...])`
queues `FauxResponseStep`s (a static `AssistantMessage` from `fauxAssistantMessage(...)` or a factory
`(context, options, state, model) => AssistantMessage`); each `stream` call shifts one and replays it as
protocol events with realistic deltas + usage estimate (faux.ts:442-476). Ports exist in Rust
(`crates/pirust-ai/src/providers/faux.rs`). `fauxToolCall(name, args, {id})` (57-64) builds tool-call
blocks; `fauxText`/`fauxThinking` build the others.

Scripted-turn recipe (a faux provider + a fake tool + capture event tape + resulting JSONL):
```ts
// tsx scripts/scripted-turn.ts  (run from packages/agent)
import { createModels, fauxProvider, fauxAssistantMessage, fauxToolCall } from "@earendil-works/pi-ai";

// turn 1: assistant asks to call "echo"; turn 2: assistant says done.
faux.setResponses([
  fauxAssistantMessage([fauxToolCall("echo", { text: "hi" }, { id: "call-1" })]),
  fauxAssistantMessage("done"),
]);

const echo: AgentTool = {
  name: "echo", label: "Echo",
  parameters: Type.Object({ text: Type.String() }),
  execute: async (_id, args) => ({ content: [{ type: "text", text: String((args as any).text) }], details: {} }),

const session = new Session(new InMemorySessionStorage());
const harness = new AgentHarness({ models, env: new NodeExecutionEnv({ cwd: process.cwd() }),
  session, model: faux.getModel(), tools: [echo] });

const tape: any[] = [];
harness.subscribe((e) => { tape.push(e.type === "message_update" ? { type: e.type } : e); });
await harness.prompt("please echo hi");
console.log("TAPE", JSON.stringify(tape.map(e => e.type)));
console.log("JSONL", (await session.getEntries()).map(e => JSON.stringify(e)).join("\n"));
```

### 11.C UUIDv7 test vectors

Pi has no injection seam (§7), so authentic (input→id) pairs cannot be extracted from Pi by injecting
clock/rng. Two options: (1) temporarily monkeypatch `globalThis.crypto.getRandomValues` and `Date.now`
in a Node tsx script, call `uuidv7()`, record `(patched now, patched 16 bytes) → id` — gives authentic
pairs from Pi's actual code; (2) reimplement per the exact layout (§7) in Rust behind an injectable
source and assert (a) hand-computed vectors, (b) version nibble `0x7X` at byte 6, variant `0b10` at
byte 8, (c) monotonic increment when `now_ms` unchanged, (d) `slice(-8)` short-id determinism. Existing
Pi self-consistency tests: `packages/agent/test/harness/session-uuid.test.ts`.

## 12. Byte/serde gotchas (must replicate)

- `undefined` fields omitted by `JSON.stringify` → `#[serde(skip_serializing_if="Option::is_none")]`;
  `null` fields (`parentId`, `leaf.targetId`) serialized explicitly → keep as `Option<T>` serialized as null.
- Object-literal key order is the wire order (§1.4). Rust struct field order = declaration order with
  `#[serde(...)]` tag first; verify with round-trip byte tests.
- UTF-16 `.length` in token estimate → `s.encode_utf16().count()`, not `.chars().count()` (compaction.ts:216).
- Inner message `timestamp` number vs outer entry `timestamp` ISO string (§1.2).
- `estimateTokens` unknown role → `0` (compaction.ts:263; asserted in test at 294).
- `createToolResultMessage`: `content ?? []`, `addedToolNames` only when non-empty (agent-loop.ts:781-783).
